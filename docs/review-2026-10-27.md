# Refactor follow-up review — 2026-10-27

Scope: React state and effects, camera ownership, frame allocations, resource cleanup, and a visually neutral Tailwind CSS v4 migration.

## Fixed

- **Camera command ordering:** three independent effects consumed selection, reset and zoom. On the first lazy mount, the reset effect could overwrite a city chosen while loading. One explicit command now survives loading and is consumed by a single adapter. Repeated Explore clicks create new focus requests.
- **Competing camera drivers:** automatic rotation could move the camera away from the transition's convergence threshold. Transition updates run before OrbitControls, with automatic rotation suspended until completion. Pointer and wheel input cancel the transition. Rapid zoom uses the pending destination so clicks accumulate and retain an ongoing focus direction.
- **Batched playback updates:** a toggle depended entirely on a render-time snapshot. The reducer now uses the latest explicit override when available, preserving two toggles queued before a render.
- **Dialog focus restoration:** React autoFocus could run before the effect captured the opener. Native showModal now owns initial focus; cleanup restores the actual opener and the previous body overflow.
- **Frame allocations:** routeWindow can fill a reusable output object. Paused routes skip their unchanged range/uniform work. Camera interpolation also reuses its scratch vectors and quaternions.

## Resource findings

No additional GPU resource leak was found in the reviewed layers. Scene geometry and materials are declared through R3F JSX; no dispose suppression was introduced. Drei owns the OrbitControls lifecycle. Camera input listeners, browser preference subscriptions and dialog side effects all have cleanup paths.

A Chromium regression observes actual WebGL buffer/program create/delete calls over four route off/on cycles. Buffers decrease on unmount and return to the original baseline on remount; programs do not accumulate. This verifies the tested route lifecycle, not every browser/GPU combination or all context-loss scenarios.

## Verification

- 17 unit regressions: reducer batching, command replay/order, camera convergence/cancellation, rapid zoom, geographic edge cases, data invariants and route timing/output reuse.
- 3 Chromium tests: dialog/reduced-motion behavior, repeated route resource disposal, and mobile controls without horizontal overflow.
- Migration comparison against commit b5fef0e: 28 UI selectors at widths 390, 760, 1100, 1280 and 1600. Computed dimensions, position, spacing, type, colors and borders matched. Fonts were blocked equally on both pages to make the comparison deterministic; desktop/mobile screenshots were inspected.
- ESLint, formatting and TypeScript/production build checks.

Existing shader colors, flight curves, route timings and city-ring behavior are unchanged. Foreground pause still renders the canvas for camera interaction; hidden tabs stop the loop. There is no claim of a universal frame rate or a full GPU benchmark. Large Three.js/data chunk warnings remain.
